# UNCAWE work plan

This document records the state of the UNCAWE implementation and what to implement next. It is not a schedule of the extensions: everything in [[extensions]] is a research proposal, and an extension enters this plan only when the user adds a corresponding card to the Part III board. The document is the tracker of all implementation and experimentation work of the project.

The document has five parts:

- **Part I:** what is implemented and reported in the [reference paper](papers/02__Uncertainty_Aware_Classifier_Accuracy_Prediction______QCDS_2026_.pdf);
- **Part II:** what is implemented in the code but not reported in the paper;
- **Part III:** the work tracker: a board of scheduled, in-progress and implemented-but-not-evaluated work, chosen by the user, and the record of completed cards;
- **Part IV:** pending fixes and known divergences between the paper and the code, which are prerequisites rather than next steps;
- **Part V:** implementation conventions for experiments, methods, results, tables and plots.

Status labels: **[paper]** implemented and reported in the paper; **[code-only]** implemented, not in the paper; **[fix]** pending correction. Work in progress is tracked by the statuses of the Part III board. Code paths are relative to `src/uncawe/` unless stated otherwise. Code names and paper names differ; the mapping is in §I.2.

Notation follows the paper: $C_{ij}=P(\hat Y=\omega_i\mid Y=\omega_j)$ and $T=C\operatorname{diag}(\pi)$, with predicted classes on rows and true classes on columns. `cap-ml` and the code store the transpose (true classes on rows).

# Part I: Implemented and reported in the paper

Everything in this part is **[paper]**. It is produced by the `main` experiment (`experiments/main.py`, entry point `uncawe.main`).

## I.1 Protocol

- **Datasets.** UCI datasets accessible through QuaPy: the 5 largest binary datasets among a list of native binary datasets and the 10 largest multiclass datasets (`experiments/datasets.py:get_filtered_datasets`).
- **Splits.** Each dataset $D$ is split with stratification into a training part (70%) and a test pool $U$ (30%); the training part is split again into $L$ (50%), used to train the classifier $h$, and $V$ (50%), used to train the CAP methods. The splits come from the `cap-ml` fetchers (`fetch_UCIBinaryDataset`, `fetch_UCIMulticlassDataset`) and are shared by all methods.
- **Classifiers.** LR, kNN, SVM (RBF kernel), MLP and RF from scikit-learn with default hyperparameters (`pretrain/classic.py`). Their posteriors on $V$ and $U$ are computed once and stored under `<CAP_DATA>/pretrain/<domain>/` (`pretrain/data.py:PretrainInfo`).
- **Target bags.** 100 bags with $\lvert U_i\rvert=1000$, drawn with replacement from $U$ at prevalence vectors sampled uniformly from the simplex. The paper calls this APP; the code uses QuaPy's `UPP` with `random_state=qp.environ["_R_SEED"]=0` (`pretrain/data.py:DatasetBundle.with_test_data`).
- **Estimand.** Every method is scored against the realised contingency table of each target bag (`true_cts`), not against the population table $C\operatorname{diag}(\pi^Q)$.

**`PQ` after FIX-1.** Since `cap-ml` `e9e77cd` (pinned by FIX-1 + FIX-4, §III.2), `PrediQuant` follows the paper's SQS-S: it splits $V$ (stratified, 50/50) into $V_1$ and $V_2$, trains the PACC(MLP) quantifier on $V_1$ only, and draws the candidate bags from $V_2$; the prevalences of the candidate bags and of the target are both estimated by the quantifier's own pipeline (the MLP, then the PACC aggregation), and $h$ is used only for the contingency tables of the bags. The stored `PQ` results of `main` were re-run with it on 2026-11-10 (`bcuda`, commit `a9ea4ed`, `main --classic --methods PQ`, 00:20–00:35, exit status $0$, $225$ files); the FIX-1 ones are kept in `<OUT_DIR>/uncawe/main_pq_pre_wp14/`. ## I.3 Evaluation

- **Point estimate:** absolute error $\operatorname{AE}=\lvert A(h,U_i)-\hat A(h,U_i)\rvert$ (`acc_err`).
- **Interval:** coverage, amplitude and Winkler score $W_i=(u_i-\ell_i)+\frac{2}{\alpha}\big(\max\{0,\ell_i-a_i\}+\max\{0,a_i-u_i\}\big)$ at $\alpha=0.05$, computed after the run from the stored samples.
- **Metric:** vanilla accuracy only.

# Part II: Implemented but not reported in the paper

Everything in this part is **[code-only]**.

## II.1 Additional metrics in `main`

`main` also evaluates macro-F1 (F1 of the positive class on binary datasets) and macro-K (macro-averaged informedness; `k_bin` on binary datasets) (`experiments/metrics.py`). Results are stored under `<OUT_DIR>/uncawe/main/<domain>/<acc_name>/`, and `tables/main.py` and `tables/rank.py` produce one table per metric. The paper reports neither metric. Contingency-table methods fit once and evaluate all three metrics on the same table samples; direct methods (`DoC`) are refitted per metric.

## II.2 The `binform` experiment

`experiments/binform.py` (entry point `uncawe.binform`) compares two BayCAP priors on `connect-4` (3 classes) with the five classifiers. Its 100 target bags have size 1000 and prevalences drawn from $\operatorname{Dir}(q)$ with $q_i=c(1-p_i)/(K-1)$, where $p$ is the validation prevalence and $c=10$ (`TEST_PRIOR_C`). Methods: `O-LEAP`, `SQS-Hbs` (called `RQBS` until 2026-11-10; stored results renamed by FIX-2), `BayesCAP_uniform` and `BayesCAP_transformed_val`, whose prior is the same transformation with $c=3$ (`BAYESCAP_PRIOR_C`). It writes the result schema of `main`. Tables: `tables/binform.py`; figure of the bag-generating and prior distributions on the ternary simplex: `plots/binform_simplex.py`.

## II.3 The `predist` experiment

`experiments/predist.py` (with `predist_config.py`, `predist_io.py`, `predist_sampling.py`; entry point `uncawe.predist`) is a diagnostic of how the distance used by `PrediQuant` ($L_1$, Hellinger, Jensen–Shannon) changes the selected neighbourhood of validation bags. It uses the 3-class datasets in `THREE_CLASS_DATASETS`, the classifiers of `--classifiers` (default since WP-16: the five of `main`, `DEFAULT_CLASSIFIERS`; before, LR only), with all (dataset, classifier) pairs in one parallel pool with `THREAD_LIMITS`, and 3–5 test prevalences at chosen points of the simplex. Since WP-16 `PrediQuant` is built as `PQ` in `main` (`build_prediquant`: PACC(MLP) through `pacc()`, $\alpha=0.1$, `predict_train_prev=True`, `rho=None`); before, it used KDEy(MLP) (`kdey()`; its MLP is seeded with the experiment seed since FIX-3, while the stored results of schema 3 come from an unseeded one). Every score is against the realised table of the test bag. It has its own result schema (`RESULT_SCHEMA_VERSION = 4` since WP-16, which adds `quantifier`, `region` and `true_dist_l1_mean`, the mean $L_1$ distance between the true prevalences of the selected bags and that of the test bag), with atomic incremental writes, and ternary plots per sample (`plots/predist.py`). The summary tables of E6.1 are `tables/predist.py` (`make run-tables-predist`): a summary and a per-region table, with the two diagnostics `test_prev_l1_error` (the $L_1$ error of the estimated prevalence of the test bag) and `pred_dist_l1_mean` (the mean $L_1$ distance of the selected bags from it in estimated-prevalence space), computed from the stored prevalences; tests: `tests/test_predist.py`. The run of E6.1 and its findings are in §II.22; the results of schema 3 (LR, KDEy(MLP)) were moved on `bcuda` to `<OUT_DIR>/uncawe/predist_kdey/` and `<OUT_DIR>/uncawe/plots/predist_kdey/`. It is not a comparison between CAP methods.

## II.4 BayCAP with a Bayesian quantifier: `BayCAPKDEy` and `BayCAPMAPLS`

`methods/baycap_kdey.py:BayCAPKDEy` (BayesKDEy) and `methods/baycap_mapls.py:BayCAPMAPLS` (BayesianMAPLS), on the common base `methods/baycap_quantifier.py:QuantifierBayCAP`, implement the methods of [[ext3_posterior_propagation]], E3.1 (tests: `tests/test_baycap_fixed.py`). Until WP-13 the eight methods were one class, `methods/baycap_fixed.py:BayCAPFixed` (WP-8, done), with a parameter `quantifier`; WP-13 split it into the two classes (user's decision of 2026-11-06), moving its code unchanged, and removed it: `tests/test_baycap_split.py` checks that the two classes give, for the same seeds, the tables, diagnostics and summaries of `BayCAPFixed` (a frozen copy at commit `55247a1`, `tests/_reference_baycap_fixed.py`) in the eight configurations, so the stored E3.1 results stay valid. (`BayCAPFixed` had itself replaced an earlier `methods/baycap_kdey.py:BayCAPKDEy`, BayesKDEy on an MLP with the population pushforward, which had no stored results; the current `BayCAPKDEy` is a different class.) `fit` measures the rate matrix of $h$ on $V$, $\hat C_{ij}=f_{ij}/n^s_j$ (no prior, not sampled), and fits a Bayesian quantifier; `predict_ct_range` samples the posterior of $\pi^Q$ with NUTS and pushes each draw through $\hat C$. Three factors: the quantifier, `BayCAPKDEy` with `c_prior="fixed"` (BayesKDEy: kernel densities of the outputs within each class on $V$, `kernel`, `bandwidth`, `shrinkage`, Dirichlet prior on $\pi$) or `BayCAPMAPLS` (BayesianMAPLS: the outputs read as calibrated probabilities, source prevalence from the labels of $V$, chain started at the EM estimate, ILR coordinates of $\pi$ from $\mathcal N(\mathbf 0,I)$, so a logistic-normal effective prior); `input_classifier`, `"h"` (the quantifier reads the `posteriors` of $h$ given to `fit` and `predict_ct_range`, and no classifier is trained) or `"mlp"` (an `MLPClassifier()` with `random_state`, its validation outputs cross-fitted on $5$ folds with `n_jobs=1`, then trained on all of $V$); `estimand`, `"population"` ($\hat C\operatorname{diag}(\pi^{(r)})$) or `"realised"` (`realised_tables` of §II.5, with $n^t$ the arg-max predictions of $h$ on the bag). `random_state` seeds NUTS, the MLP and the multinomial draws, so the two estimands of a cell share their prevalence draws; seeding the MLP solves the `BayCAPKDEy` item of FIX-3. The input classifier, $\hat C$, the NUTS run, the pushforward of a fixed $\hat C$, the diagnostics, `accuracy_moments` and `top_label_ece` are in `QuantifierBayCAP`; the NUTS models and their preparation (`baycap_kdey.py:kdey_model`, `baycap_mapls.py:emq_model`, `ilr`, `ilr_inverse`) are copied from QuaPy's `quapy.method._bayesian` (commit `31f36f6` of `devel`), because QuaPy builds `BayesianKDEy` and `BayesianMAPLS` only when `pystan` is installed and `pystan` is not in the environment (user's decision of 2026-11-03); the kernel densities are QuaPy's (`quapy.method._kdey.KDEBase`) and the EM start is QuaPy's `mapls`. A test restores the modules that QuaPy disables without `pystan` and checks that the draws equal those of QuaPy's `sample_from_posterior` for both quantifiers. After each `predict_ct_range` call, `last_nuts_diagnostics` returns the divergent transitions, the largest split-$\hat R$ and the smallest effective sample size of $\pi$ (`nuts_diagnostics` of §II.5), and `last_posterior_summaries` the vanilla-accuracy summaries `prev_mean` ($\bar\pi$), `acc_sd` ($\sigma_p$, the standard deviation of $\sum_j\hat C_{jj}\pi^{(r)}_j$), `sigma_g` ($\bar\sigma_g$ of §T.8 of [[ext3_posterior_propagation]], `accuracy_moments`) and `val_ece` (top-label ECE, $15$ bins, of the input classifier on its validation outputs, `top_label_ece`).

In `main`, the eight methods `BayCAP-<Q>-<s>` and `BayCAP-<Q>-<s>-real` ($Q\in\{$`KDEy`, `EMQ`$\}$, $s\in\{$`h`, `mlp`$\}$) are in `experiments/methods.py:FIXED_C_VARIANTS` (Gaussian kernel, bandwidth $0.1$, no shrinkage, $\tau=1$, the NUTS settings and default seed of the BayCAP methods) and run in the BayCAP pool, which now holds the methods of `BAYES_POOL_METHODS` (the BayCAP methods of §II.5 and these eight) instead of every method whose name contains `BayesCAP`; `main` stores their NUTS diagnostics and summaries per bag (§V.3). Since 2026-11-09 (user's decision) `BayCAP-KDEy-mlp-real` is in the tables of `main` (`tables/main.py:MAIN_METHODS`), in its ranks and in the coverage vs amplitude plot, but not in its other default plots; the other seven are in no table, rank or default plot of `main` (`tables/main.py:EXCLUDED_METHODS`; from 2026-11-05 to 2026-11-09 `BayCAP-KDEy-h-real` was shown too). The analysis of E3.1 is `tables/baycap_fixed.py` and `plots/baycap_fixed.py` (tests: `tests/test_baycap_fixed_tables.py`): per pair, the scores of the eight methods, `BayesCAP`, `BayesCAP-real`, `BayesCAP-Hf-real` and `SQS-Hbs` (`RQBS` before FIX-2); per cell, the observed and predicted widening factors, the movement of the centre, the label-free mismatch $\lVert n^t/N^Q-\hat C\bar\pi\rVert_1$ and the NUTS diagnostics; the ECE of the two input classifiers and $\operatorname{sd}_j(\hat C_{jj})$; sixteen paired bootstrap tests of the mean Winkler difference (four against `BayesCAP-Hf-real`), each Holm-adjusted over the pairs; coverage in bins of $\min_j\pi^Q_j$; the $2\times2$ design per pushforward and metric. In the realised and population tables the columns are grouped by score (AE, amplitude, coverage, Winkler score; `TABLE_SCORES`) and then by method, and in each row and score group the cells are coloured from the worst to the best value, with the best in bold (lower is better for AE, amplitude and Winkler score, closer to $0.95$ for coverage; `_score_cell_styles`). `tables/displacement.py --method` gives these methods a prior part $R_0=0$ (`method_c_prior` returns `"none"`), and `tables/rank.py --include-e31` (or `--include <methods>`) ranks them with the methods of `main`, under `<OUT_DIR>/uncawe/tables/rank/extended/`. Evaluated by E3.1.

`BayCAPKDEy` with `c_prior="hierarchical-f"` (WP-13, done; evaluated by E3.2; tests: `tests/test_baycap_kdey_hf.py`) implements the methods of [[ext3_posterior_propagation]], E3.2: BayCAP-KDEy with a random $C$. `fit` splits each class $\omega_j$ of $V$ into the cells $V_{kj}$ of the instances that $h$ predicts as $\omega_k$ and fits one kernel density $\hat\phi_{kj}$ per cell (QuaPy's `KDEBase`, the kernel and bandwidth of BayesKDEy) on the validation outputs of the input classifier (cross-fitted for `mlp`), so that $\sum_k\hat C_{kj}\hat\phi_{kj}$ is the class density of BayesKDEy; an empty cell takes the density of all the validation instances that $h$ predicts as $\omega_k$ (`CELL_PREDICTED`), or the class density $\hat f_j$ if $h$ never predicts $\omega_k$ on $V$ (`CELL_CLASS`), recorded in `cell_source_`. Per bag, `cell_log_densities` computes the log-densities of the cells at the target outputs before sampling (all $K^2$ for `h`, the $K$ cells of the prediction of $h$ for `mlp`), and NUTS samples $(\pi,C)$ jointly with `kdey_hf_model`: $\pi\sim\operatorname{Dir}(\mathbf 1)$, the Hf prior on $C$ with centred shares (`methods/baycap.py:hierarchical_rate_sites`, shared with `BayCAP`, so the two models have the same sites), the validation counts observed as multinomials, and the log-likelihood of the bag `kdey_hf_loglik` divided by $\tau$: $\sum_u\log\sum_j\pi_j\sum_kC_{kj}\hat\phi_{kj}(z_u)$ for `h` (outputs alone), $\sum_u\log\sum_j\pi_jC_{\hat y_uj}\hat\phi_{\hat y_uj}(z_u)$ for `mlp` (outputs and predictions of $h$), both by log-sum-exp. Each draw gives $C^{(r)}\operatorname{diag}(\pi^{(r)})$, then the estimand applies; `main` uses the realised one. The NUTS diagnostics cover $\pi$, $C$, $m$, $\rho$ and $1/(1+\kappa)$; `last_posterior_summaries` returns `KDEY_HF_SUMMARIES`: the summaries of `BayesCAP-Hf-real` (`hierarchical_summaries` with those of $\kappa$) and `c_mean`, `c_sd` (posterior mean and standard deviation of $C$, `cap-ml` layout, flattened row by row), `mismatch` ($\lVert n^t/N^Q-\bar C\bar\pi\rVert_1$), `n_empty_cells`, `n_class_density_cells` and `val_ece`. A failed start of NUTS is handled as in `BayesCAP-Hf-real` (NaN tables and diagnostics, `nuts_failed=1`). In `main`, the methods `BayCAP-KDEy-Hf-h-real` and `BayCAP-KDEy-Hf-mlp-real` are in `experiments/methods.py:KDEY_HF_VARIANTS` (the kernel of E3.1, `KDEY_SETTINGS`, $\tau=1$, the NUTS settings and default seed of the BayCAP methods), run in the BayCAP pool; they are in no table, rank or default plot of `main` (`tables/main.py:EXCLUDED_METHODS`; on the branch of WP-13, from 2026-11-06 to the merge, they were in its tables, ranks and coverage vs amplitude plot at the user's request, and the tables of `main` of 2026-11-09 were generated with them); `tables/rank.py --include-e32` adds them to the extended rank table too, and `tables/displacement.py --method` accepts them, with a prior part $R_0$ of NaN (as for every method with a hierarchical prior, whose posterior mean of a recall given $V$ alone has no closed form). ## II.5 The `BayCAP` method with population or realised-table estimand

`methods/baycap.py:BayCAP` copies the BayesianCC model, priors and NUTS sampler of `cap-ml` `ACC_BayesCAP` (commit `bb20aa5` of `devel`) and adds the hyperparameter `estimand`. With `"population"` (default) it returns the population tables $C^{(r)}\operatorname{diag}(\pi^{(r)})$, identical to `ACC_BayesCAP` for the same `random_state`. With `"realised"` it returns the realised-table posterior predictive: for each draw and each predicted class $\omega_i$, the true classes of the $n^t_i$ target instances predicted as $\omega_i$ are drawn as $\operatorname{Mult}(n^t_i,\rho^{(r)}_{i\cdot})$, with $\rho^{(r)}_{ij}=C^{(r)}_{ij}\pi^{(r)}_j/\sum_l C^{(r)}_{il}\pi^{(r)}_l$ (module-level function `realised_tables`). Both estimands represent the uncertainty on $\pi^Q$ and $C$; only `"realised"` also represents the finite-sample fluctuation of the target table, which is what the experiments score. Both share the NUTS draws for the same `random_state`; the multinomial draws use a NumPy generator seeded with `random_state`. Method names: `BayesCAP` and `BayesCAP-real` (labels in `tables/common.py` and `plots/common.py`). It has unit tests (`tests/test_baycap.py`). Since WP-4 `BayCAP(acc, estimand="realised")` is the method `BayesCAP-real` of `main` (`experiments/methods.py`, same NUTS settings and default seed as `BayesCAP`), run with the BayCAP methods; its results are stored for all 75 pairs and all three metrics (run ended 2026-10-22), and E2.3 of [[ext2_baycap]] evaluates it (§II.13). It is excluded from the tables and ranks of `main` (`tables/main.py:EXCLUDED_METHODS`) and from the default methods of its plots (tests: `tests/test_methods.py`); the comparison of the two pushforwards is in §II.13. Source: WP-1; added to `main` by WP-4 (§III.3).

The hyperparameter `c_prior` selects the prior on the columns of $C$ (evaluated by E2.4 of [[ext2_baycap]], §II.14). `"uniform"` (default) is $\operatorname{Dir}(\mathbf 1_K)$, as in `ACC_BayesCAP`, with unchanged NUTS draws. `"empirical-bayes"` gives column $j$ the prior $\operatorname{Dir}(\alpha_{\cdot j})$ with $\alpha_{jj}=\hat\nu\hat m$ and $\alpha_{ij}=\hat\nu(1-\hat m)/(K-1)$ for $i\ne j$ (`eb_concentration`), so that the recall $C_{jj}$ has the prior $\operatorname{Beta}(\hat\nu\hat m,\hat\nu(1-\hat m))$; in the `cap` layout a column of $C$ is a row of `p_c_cond_y`, and the matrix is symmetric. `fit` estimates $(\hat m,\hat\nu)$ from the diagonal counts $f_j$ and the class totals $n_j$ of the validation table by maximising the beta-binomial log-likelihood $\sum_j[\ln B(f_j+\nu m,\,n_j-f_j+\nu(1-m))-\ln B(\nu m,\,\nu(1-m))]$ (`beta_binomial_loglik`, `fit_beta_binomial`): L-BFGS-B over $(\operatorname{logit}m,\ln\nu)$ with the analytic gradient, from the pooled recall and $\ln\nu\in\{0,3,6\}$, within $m\in[10^{-3},1-10^{-3}]$ and $10^{-3}\le\nu\le10^4$ (`EB_M_BOUNDS`, `EB_NU_BOUNDS`; the lower bound on $\nu$ is a numerical safeguard). The fit is stored as `eb_fit` (`BetaBinomialFit`: $\hat m$, $\hat\nu$, whether each reached a bound, $\operatorname{sd}(\hat m)$ and the maximum log-likelihood) and the concentrations as `c_alpha`. $\operatorname{sd}(\hat m)=\hat m(1-\hat m)\operatorname{sd}(\operatorname{logit}\hat m)$ comes from the inverse of the observed information (central differences of the gradient); with $\hat\nu$ on a bound only the curvature in $\operatorname{logit}m$ is used, and with $\hat m$ on a bound it is NaN. The likelihoods, the prior on $\pi^Q$, NUTS, the seed and both estimands are unchanged. Source: WP-5 (§III.3).

`c_prior="hierarchical"` (WP-10; evaluated by E2.7 of [[ext2_baycap]] as `BayesCAP-H-real`, §II.17) samples the prior on the recalls with NUTS instead of plugging in a fit: $m\sim U(0,1)$ and $u=1/\sqrt{1+\nu}\sim U(0,1)$ (sites `h_m`, `h_u`; `nu_from_u` gives $\nu=1/u^2-1$, with density $\frac12(1+\nu)^{-3/2}$), the recalls $C_{jj}\mid m,\nu\sim\operatorname{Beta}(\nu m,\nu(1-m))$ in a plate over the classes (`h_recalls`), and the mistakes of each true class shared among the other classes by $\operatorname{Dir}(\mathbf 1_{K-1})$ (`h_shares`, only for $K\ge3$); `hierarchical_rates` builds `p_c_cond_y` (row $j$ is the column $C_{:j}$) as a deterministic site. The parametrisation is centred, with no bound on $\nu$. `fit` stores no concentrations (`c_alpha` is `None`). `last_posterior_summaries` returns, for the last `predict_ct_range` call, the summaries of `hierarchical_summaries` (`HIERARCHICAL_SUMMARIES`: posterior mean of $m$; median, $5\%$ and $95\%$ quantiles of $\ln\nu$; $P(\nu>\min_jn_j)$; posterior means of the recalls and of $\pi^Q$; covariance of $\pi^Q$, flattened), and an empty dict for the other priors. If NUTS finds no valid initial parameters, the bag gets tables of NaN, NaN diagnostics and `nuts_failed=1` (`failed_summaries`); the other priors raise as before.

`c_prior="hierarchical-f"` (WP-11; evaluated by E2.8 of [[ext2_baycap]] as `BayesCAP-Hf-real`, §II.18) is `"hierarchical"` with two changes (§T.16): $\rho=1/(1+\nu)\sim U(0,1)$ (site `h_rho`; `strength_from_rho` gives $\nu=1/\rho-1$, with density $(1+\nu)^{-2}$ and $P(\nu>x)=1/(1+x)$) instead of $u$, and, for $K\ge3$, a common concentration $\kappa$ of the shares of the mistakes, $1/(1+\kappa)\sim U(0,1)$ (site `h_rho_kappa`, deterministic `h_kappa`), with `h_shares` $\sim\operatorname{Dir}(\kappa\mathbf 1_{K-1})$; with $K=2$ there is no $\kappa$. Its NUTS diagnostics cover $m$, $\rho$ and $1/(1+\kappa)$ with $\pi^Q$ and $C$; its posterior summaries add `KAPPA_SUMMARIES` (median, $5\%$ and $95\%$ quantiles of $\ln\kappa$, $P(\kappa<1)$, from `kappa_summaries`; NaN with $K=2$); a failed start is handled as for `"hierarchical"`. The hyperparameter `shares` (WP-12; evaluated on a pilot only by E2.9 of [[ext2_baycap]] as `BayesCAP-Hfn-real`, §II.19, `experiments/methods.py:BAYCAP_OPTIONS`) selects the coordinates of the shares of `"hierarchical-f"` (§T.17): `"centred"` (default, the Dirichlet site `h_shares` of WP-11, draws unchanged) or `"non-centred"`, which samples `h_shares_gamma` $G'_{ij}\sim\operatorname{Gamma}(\kappa+1,1)$ and `h_shares_exp` $e_{ij}\sim\operatorname{Exp}(1)$ on the off-diagonal cells and makes `h_shares` deterministic, $\operatorname{softmax}$ over each column of $\ln G'_{ij}-e_{ij}/\kappa$ (`noncentred_shares`), the same law $\operatorname{Dir}(\kappa\mathbf 1_{K-1})$ given $\kappa$; the NUTS diagnostics and the posterior summaries are those of `"hierarchical-f"`, on the same sites; any other prior with `"non-centred"` raises an error. With $K=2$ the two forms give the same draws.

**The BayCAP methods of `main` and their NUTS diagnostics** (WP-6). `experiments/methods.py:BAYCAP_VARIANTS` gives the estimand and `c_prior` of the four BayCAP methods of `main`, all `BayCAP` with the NUTS settings and seed of §I.2: `BayesCAP` (population, uniform; §I.2), `BayesCAP-real` (realised, uniform), `BayesCAP-EB` (population, empirical Bayes) and `BayesCAP-EB-real` (realised, empirical Bayes). The two empirical-Bayes methods are, like `BayesCAP-real`, excluded from the default plots of `main` and used by E2.4 of [[ext2_baycap]]; A fifth method, `BayesCAP-H-real` (realised, hierarchical; WP-10, §II.17), and a sixth, `BayesCAP-Hf-real` (realised, `"hierarchical-f"`; WP-11, §II.18), are in `BAYCAP_VARIANTS`. Since 2026-11-05 (user's request) the tables and ranks of `main` show `BayesCAP-Hf-real`, and since 2026-11-06 (user's request) `BayesCAP-EB-real` again, and none of the other four variants (`tables/main.py:IN_TABLES`, §V.4; before 2026-11-05, the tables showed `BayesCAP-EB-real` and `BayesCAP-H-real`), and the coverage vs amplitude plot (`plots/amplitude_vs_coverage.py:PLOT_METHODS`) shows `BayesCAP-real`, `BayesCAP-EB-real` (since 2026-11-06) and `BayesCAP-Hf-real` (before 2026-11-05, `BayesCAP-real`, `BayesCAP-EB`, `BayesCAP-EB-real` and `BayesCAP-H-real`); no variant is in the other default plots. `experiments/eb_binary.py` keeps the four methods of E2.4. After each `predict_ct_range` call, `BayCAP.last_nuts_diagnostics` returns the number of divergent transitions, the largest split-$\hat R$ (the single chain split in two halves) and the smallest effective sample size over the entries of $\pi^Q$ and $C$ (`nuts_diagnostics`, with `numpyro.diagnostics`); the draws are those without the diagnostics. `experiments/main.py` stores them for every bag of a `BayCAP` method as the optional columns `nuts_divergences`, `nuts_max_rhat`, `nuts_min_ess` (§V.3), computed outside the timed calls; for `BayesCAP-H-real` the diagnostics also cover $m$ and $u$ (for `BayesCAP-Hf-real` $m$, $\rho$ and $1/(1+\kappa)$), and the posterior summaries of `last_posterior_summaries` are stored next to them (§V.3). `tables/eb_prior.py` and `plots/eb_prior.py` implement the E2.4 analysis (§II.14). Source: WP-6 (§III.3).

## II.10 The estimand-gap analysis of BayCAP

`tables/estimand_gap.py` (tests: `tests/test_estimand_gap.py`) approximates, on stored `main` results and without new runs, how a realised-table posterior predictive would change BayCAP's accuracy intervals ([[ext2_baycap]], E2.1). `main` stores BayCAP's accuracy samples but not its table draws, so the predictive is approximated for accuracy only: each approximate predictive sample is the stored accuracy sample plus independent $\mathcal N(0,\hat\sigma_g^2)$ noise, with $\hat\sigma_g^2=\sum_i n^t_i\bar\rho_{ii}(1-\bar\rho_{ii})/(N^Q)^2$, $n^t$ the predicted counts of the bag and $\bar\rho$ the stored mean table `estim_cts` (paper layout) with each row normalised to one; both are label-free, and labels are used only for scoring against the realised table (`true_cts`). Per (dataset, classifier) pair, at $\lvert U\rvert=1000$ and for vanilla accuracy, it reports coverage, amplitude and Winkler score ($\alpha=0.05$) of BayCAP and of the approximate predictive, the ratio $\hat\sigma_g/\hat\sigma_p$, the median number of validation instances per class, a gate summary and suggested pilot datasets, as LaTeX and PDF. The noise is seeded per pair (seed $0$).

- **Run:** 2026-10-14, local run on `eosisti` (`OUT_DIR=./output`), on the old `BayesCAP` results (§I.2, kept in `<OUT_DIR>/uncawe/main_22_10_26/`). Generated again on 2026-10-22 on `BayesCAP` recomputed on CPU, by the user, and copied locally with `make pull` (PDF built at commit `a23fb97`); results under `<OUT_DIR>/uncawe/tables/estimand_gap/`, read by E2.3 (`tables/pushforward.py`). `cap-ml` commit: not recorded at run time (`cap-ml` is pinned to the `devel` branch, FIX-4, and `uv.lock` is not tracked).
- **Findings** (75 pairs, CPU results): 53 under-cover (coverage below $0.90$); 5 are brought within $[0.93,0.97]$ with a lower Winkler score (3 on the old results); 24 have $\hat\sigma_g/\hat\sigma_p<0.3$; 56 have a lower Winkler score under the approximation. The ratio ranges from $0.07$ (`poker_hand` LR) to $1.78$ (`letter` RF; $1.50$, `dry-bean`, on the old results). On large-$K$ datasets BayCAP is biased low (LR: `isolet` $-0.18$, `letter` $-0.07$), and its coverage is $0.00$ on `isolet` and `letter` for every classifier. ## II.11 The displacement analysis of BayCAP

`tables/displacement.py` and `plots/displacement.py` (tests: `tests/test_displacement.py`) explain, on stored `main` results and without new runs, why BayCAP's accuracy intervals are displaced ([[ext2_baycap]], E2.2). BayCAP targets the population table and is scored against the realised table (`true_cts`); the analysis uses target labels and is not a method. Per (dataset, classifier) pair, at $\lvert U\rvert=1000$ and for vanilla accuracy, it splits the error of BayCAP's point estimate in each bag into a recall term and a prevalence term, $\hat A-A=\sum_j\pi_j(\hat r_j-r_j)+\sum_j(\hat\pi_j-\pi_j)\hat r_j$, with $\hat\pi,\hat r$ from the stored mean table `estim_cts`; it computes the prior part of the recall term on the validation counts $f_{ij}$ rebuilt from the stored validation posteriors and labels, $\sum_j\pi_j\left(\frac{f_{jj}+1}{n^s_j+K}-\frac{f_{jj}}{n^s_j}\right)$ (for the empirical-Bayes methods of §II.5, $\frac{f_{jj}+\hat\nu\hat m}{n^s_j+\hat\nu}$ in place of $\frac{f_{jj}+1}{n^s_j+K}$: `method_c_prior`, `smoothed_recalls`; WP-6); and it reports the conditioning of $\hat C$ on vectors summing to zero ($\kappa_0$ and $1/\sigma_{\min}$, from the singular values of $Q^\top\hat CQ$), the accuracy of $h$ on $V$, coverage, amplitude, Winkler score, and the coverage $\mathcal C_s$ predicted from the mean shift and amplitude alone (normal approximation). Outputs: a per-pair CSV and one table (diagnostics, interval, error) as LaTeX and a landscape PDF under `<OUT_DIR>/uncawe/tables/displacement/`; two scatters (recall term against its prior part; $1/\sigma_{\min}$ against accuracy on $V$, coloured by coverage and by shift) under `<OUT_DIR>/uncawe/plots/main/displacement/`. Both scripts take the method as `--method` (default `BayesCAP`); for any other method, e.g. `BayesCAP-real` (WP-4), the outputs go to a subfolder named after the method of these two folders.

- **Run:** 2026-10-20 on `bcuda`, all 75 pairs (commit `e0e2f94`, dirty only for a local `WHERE` default in the `Makefile`; Python 3.12.11; `cap-ml` `bb20aa5`); results under `<OUT_DIR>/uncawe/tables/displacement/` and `<OUT_DIR>/uncawe/plots/main/displacement/`, copied locally with `make pull`; table regenerated with the merged layout on 2026-10-20. On 2026-10-22 the table was generated again by the user on `BayesCAP` recomputed on CPU (§I.2), now with the predicted coverage $\mathcal C_s$, and for `BayesCAP-real` (WP-4, `--method BayesCAP-real`, under `<OUT_DIR>/uncawe/tables/displacement/BayesCAP-real/`); the two scatters were drawn again on 2026-10-23 on `bcuda` (commit `975f2ac`) for both methods, the ones of `BayesCAP-real` under `<OUT_DIR>/uncawe/plots/main/displacement/BayesCAP-real/`.
- **Findings** (the same on the old and on the CPU results): coverage follows the coverage predicted from the shift alone (correlation $0.98$; 10 pairs more than $0.05$ below it on the CPU results); the $\operatorname{Dir}(\mathbf 1)$ prior on $C$ accounts for every pair with coverage near $0$ (large $K$, recall term equal to its prior part); a badly conditioned $\hat C$ displaces the interval only when the prevalence error has the same sign in every bag (`german`, `wine-quality`), and otherwise widens it; the accuracy of $h$ on $V$ does not act on its own; on binary datasets a smaller recall error remains that the prior does not explain. Consistency checks: the mean of the accuracy samples equals the accuracy of the mean table within $1.3\cdot10^{-6}$; coverage agrees with E2.1 (53 of 75 pairs below $0.90$); $\hat C$ is singular on vectors summing to zero for 7 pairs.
- **Inputs:** the first run used the old `BayesCAP` results (§I.2), kept in `<OUT_DIR>/uncawe/main_22_10_26/`; the table of 2026-10-22 uses the CPU results.
- **Card:** WP-3 (§III.3).

## II.20 The error split and the oracle 2×2 of the main-table methods

`error_split.py` (pure numpy; tests: `tests/test_error_split.py`) splits the error $\hat A-A(h,U)$ of a method that estimates a contingency table into the prevalence part $e_1=\sum_j(\tilde\pi_j-\pi^Q_j)\tilde d_j$, the recall part $e_2=\sum_j\pi^Q_j(\tilde d_j-d^{\text{pool}}_j)$ and the luck of the bag $e_3=\sum_j\pi^Q_j(d^{\text{pool}}_j-c_j/n_j)$ ([[ext4_uncertainty_budget]] §T.2), with the cross term $x=\sum_j(\tilde\pi_j-\pi^Q_j)(\tilde d_j-d^{\text{pool}}_j)$ and the four oracle estimates $\sum_j\pi_jd_j$, $\pi\in\{\tilde\pi,\pi^Q\}$, $d\in\{\tilde d,d^{\text{pool}}\}$ (§T.5). $\tilde\pi$ and $\tilde d$ are read from the stored mean table `estim_cts`, $\pi^Q$ and $c_j/n_j$ from `true_cts` (both in the `cap-ml` layout, true classes on rows, normalised), and $d^{\text{pool}}$ from the argmax of the pretrain `U_posteriors` against the pool labels. Conventions: a class absent from the bag contributes $0$ to $e_3$; a class with an empty estimated column gets $\tilde d_j:=d^{\text{pool}}_j$ (its contribution goes to $e_1$), and such bags are counted; bags where NUTS failed are dropped and counted. The split uses the true prevalences and the pool labels, so it is an analysis, and the three oracle cells are references.

`tables/error_split.py` applies it to the stored `main` results (vanilla accuracy, $\lvert U\rvert=1000$) of `QuAcc_NxN`, `O-LEAP`, `RQBS` (`SQS-Hbs` since FIX-2, which also adds `SQS-H`), `PQ`, `BayesCAP-real`, `BayesCAP-Hf-real`, `BayCAP-KDEy-mlp-real` (`DoC` estimates no table), scored against the realised table of each bag: a per-bag CSV, a per-pair CSV, E4.1 tables A (RMS of the parts and of the total, coloured per row and group, superscript naming the part with the largest RMS, a row with the share of pairs in which each part is the largest) and B (signed means), and the two E4.3 tables (mean AE of the four cells against the realised and against the pool accuracy, with the mean and RMS of $x$); `--tables-set e4.1|e4.3`; checks of the identity and counts of dropped and empty-column bags are printed. `plots/error_split.py` draws the E4.1 bar plots: the mean square of each part, stacked on a linear scale with a dot for the total, one panel per dataset for every method but `QuAcc_NxN` (`--figures bars`), and `QuAcc_NxN` alone, one bar per dataset (`--figures bars-quacc`).

- **Run:** 2026-11-10, on `bcuda` (tables from `24b6776`, bar plots from `45a69b5`), `cap-ml` `87b4d9b`, on the stored results of `main` with `PQ` re-run with that commit so that it stores its table (§I.2); outputs under `<OUT_DIR>/uncawe/tables/error_split/` and `<OUT_DIR>/uncawe/plots/main/error_split/`, pulled and PDFs built locally. Checks: the identity holds within $10^{-14}$ on every bag for every method except `O-LEAP` ($8.1\cdot10^{-11}$) and `QuAcc_NxN` (up to $1.5\cdot10^{-6}$ on 11 pairs: its stored estimate is not exactly the trace of its stored mean table); no bag dropped; empty-column bags: `QuAcc_NxN` 838, `RQBS` 910, BayCAP-KDEy 11.
- **Findings** (the Analysis sections of E4.1 and E4.3 in [[ext4_uncertainty_budget]]): $e_3$ (RMS $\approx0.009$–$0.010$) is a common floor that makes up most of the error of the best methods on the easy datasets; on binary datasets $e_2$ dominates and is mostly a constant offset per pair, positive for every method (mostly `mammographic` and `german`, the smallest $V$; smaller for RF and kNN), ascribed as a hypothesis to the finite $V$ (to be tested by E4.2); on multiclass datasets $e_1$ weighs more, and with the true prevalence the best methods come close to the floor; `BayesCAP-real` underestimates the recalls as $K$ grows and `BayesCAP-Hf-real` removes it; `QuAcc_NxN` has very large parts that partly cancel (large negative $x$), and the true prevalence makes it worse.
- **Card:** WP-14 (§III.3).

## II.21 The allocation $\rho$ of the validation set in `PrediQuant` (not evaluated)

Since `cap-ml` `0f25e9e` (version 0.1.1.12; pinned since `637fdd5`, version 0.1.1.13, by FIX-2 + FIX-3), `PrediQuant` (`cap-ml` `src/cap/models/confidence.py`; tests: `tests/test_prediquant.py`) has a parameter `rho`, the share $\rho=\lvert V_1\rvert/\lvert V\rvert$ of the validation set that trains the quantifier; the rest, $V_2$, is where the candidate bags are drawn from. With `rho=None` (the default, used by `PQ`, §I.2) the split is the stratified 50/50 `train_test_split` seeded by `random_state`, as before. With $\rho\in(0,1)$ (`_split`), the validation indices of each class $\omega_j$ are permuted once with a `RandomState(random_state)` (classes in the order of `val.classes_`) and $V_1$ takes the first $\operatorname{round}(\rho\lvert V_j\rvert)$ of them (half rounded up); since the permutations do not depend on $\rho$, for the same seed $V_1(0.1)\subset V_1(0.3)\subset\dots\subset V_1(0.9)$. A $\rho$ outside $(0,1)$, or one that leaves a class empty in $V_1$ or in $V_2$, raises `ValueError`. After `fit`, `PrediQuant` keeps the indices in $V$ of the two parts (`Vq_idx`, `Vb_idx`), the positions in $V_2$ of the instances of each candidate bag (`sigma_indices`) and the labels of $V_2$ (`Vb_y`); after each `predict_ct_range` call (and so after `predict_ct`, `predict_range`, `predict`), it keeps the estimated prevalence $\hat\pi^Q$ of the target (`last_test_prev`, equal to `q.predict` on the target) and the positions of the selected candidate bags (`last_selected_bags`). `class_support(selected_bags=None)` returns, for each class, the number of distinct instances of that class in $V_2$ that appear in at least one selected bag (by default, the bags of the last prediction), divided by the number of instances of that class in $V_2$. The estimand is unchanged: SQS-S targets the realised table of the target bag. No UNCAWE code uses `rho` or the new attributes yet; E6.2 of [[ext6_sqs_s_design]] (card WP-17) will. Card: WP-15 (§III.3).

### WP-14 E4.1 + E4.3: the error split and the oracle 2×2 of the main-table methods on stored `main` results

- **Goal:** evaluate CAP methods that push the joint posterior draws $\pi^{(r)}$ of a Bayesian quantifier through the rate matrix of $h$ measured on $V$, $\hat C\operatorname{diag}(\pi^{(r)})$ with $\hat C_{ij}=f_{ij}/n^s_j$ (no prior, not sampled), and separate the effect of three components. ### WP-12 E2.9: BayCAP-Hfn, BayCAP-Hf with non-centred shares of the mistakes, on the pairs of `main`

- **Kind / status:** experiment / Done (check and pilot only; full run not done, user decision)
- **Source:** [[ext2_baycap]] (E2.9, §T.17)
- **Goal:** run BayCAP-Hf (`BayesCAP-Hf-real`, WP-11) with the shares of the mistakes sampled in a non-centred form, the same model, to remove the divergences of its centred Dirichlet. Background: BayCAP-Hf has $m\sim U(0,1)$, $1/(1+\nu)\sim U(0,1)$, recalls $C_{jj}\mid m,\nu\sim\operatorname{Beta}(\nu m,\nu(1-m))$, and the off-diagonal cells of column $j$ equal to $(1-C_{jj})s_j$ with $s_j\mid\kappa\sim\operatorname{Dir}(\kappa\mathbf 1_{K-1})$ and $1/(1+\kappa)\sim U(0,1)$. Its run (E2.8) found it the best BayCAP prior on the $52$ pairs where NUTS is reliable, but more than $1\%$ of the draws divergent on $18$ pairs where BayCAP-H was clean (all of `poker_hand` and `isolet`, `nursery` LR, SVM, MLP, RF, `wine-quality` LR, SVM, RF, `shuttle` MLP), where the posterior median of $\kappa$ is about $e^{-3}$ to $e^{-1.7}$ and the shares of columns with few observed mistakes follow $\kappa$ through a funnel.
  - *Method:* `BayesCAP-Hfn-real`: the model of `BayesCAP-Hf-real`; for $K\ge3$, for each off-diagonal cell, $G'_{ij}\sim\operatorname{Gamma}(\kappa+1,1)$ and $e_{ij}\sim\operatorname{Exp}(1)$, $\ln g_{ij}=\ln G'_{ij}-e_{ij}/\kappa$, $s_{ij}=g_{ij}/\sum_{k\ne j}g_{kj}$ (computed in logs), which gives exactly $s_j\mid\kappa\sim\operatorname{Dir}(\kappa\mathbf 1_{K-1})$. ### WP-6 E2.4: BayCAP with an empirical-Bayes prior on the recalls

- **Kind / status:** experiment / Done (2026-10-28)
- **Source:** [[ext2_baycap]] (E2.4)
- **Result:** §II.14 (code, run, findings); the BayCAP methods of `main` and `c_prior` in §II.5; the `BayCAP` row of §II.12

### WP-5 Empirical-Bayes prior on the columns of $C$ for `BayCAP`

- **Kind / status:** method / Done (2026-10-26)
- **Source:** [[ext2_baycap]] (E2.4, §T.9)
- **Result:** §II.5 (`c_prior`, not evaluated); the `BayCAP` row of §II.12
- **Goal (as planned):** add to `BayCAP` (`src/uncawe/methods/baycap.py`) a hyperparameter `c_prior` that selects the prior on the columns of $C$. `"uniform"` (default) is $\operatorname{Dir}(\mathbf 1_K)$, the current model, unchanged. `"empirical-bayes"` gives column $j$ the prior $\operatorname{Dir}(\alpha_{\cdot j})$ with $\alpha_{jj}=\hat\nu\hat m$ and $\alpha_{ij}=\hat\nu(1-\hat m)/(K-1)$ for $i\ne j$, so that the recall $C_{jj}$ has the prior $\operatorname{Beta}(\hat\nu\hat m,\hat\nu(1-\hat m))$. $(\hat m,\hat\nu)$ are fitted in `fit` by maximising the beta-binomial log-likelihood $\sum_j[\ln B(f_j+\nu m,\,n_j-f_j+\nu(1-m))-\ln B(\nu m,\,\nu(1-m))]$ of the diagonal counts $f_j$ of the validation table, out of the $n_j$ validation instances of each class, numerically over $(\operatorname{logit}m,\ln\nu)$, within $\nu\le10^4$ and $m\in[10^{-3},1-10^{-3}]$; the fit stores $\hat m$, $\hat\nu$, whether a bound was reached, and $\operatorname{sd}(\hat m)$ from the curvature of the log-likelihood at its maximum. Everything else of the BayesianCC model is unchanged: the likelihoods of $V$ and of the target predicted counts, the prior on $\pi^Q$, NUTS, the seed, and both estimands. In the `cap` layout a column of $C$ is a row of `p_c_cond_y`, so the concentration matrix is built transposed. Why: the $\operatorname{Dir}(\mathbf 1)$ prior pulls every recall towards $1/K$, which displaces BayCAP's interval on datasets with large $K$ and accurate classifiers; the empirical-Bayes prior pulls each recall towards the typical recall of the classifier.
- **Estimand:** as `BayCAP`: population table with `estimand="population"`, realised table with `estimand="realised"`.
- **Scope:** `methods/baycap.py` (`c_prior`, the fit of $(\hat m,\hat\nu)$, the concentration matrix in `model`); `tests/test_baycap.py`; §II.5 and the `BayCAP` row of §II.12. Not in this card: the methods of `main`, the diagnostics and the E2.4 analysis (WP-6).
- **Depends on:** none.
- **Comparability:** with `c_prior="uniform"` the model and the NUTS draws are unchanged, so no stored result changes.
- **Deviations from Part V:** none expected.
- **Done when:** code and tests are merged into `devel`, and §II.5 describes `c_prior` as not evaluated. The tests check that the log-likelihood matches `scipy.stats.betabinom`; that the fit recovers $(m,\nu)$ on synthetic counts with many classes; that, when all classes share one recall, the fit reaches the upper bound of $\nu$ and gives $\hat m=\sum_jf_j/\sum_jn_j$; that the concentration matrix has diagonal $\hat\nu\hat m$ and off-diagonal sums $\hat\nu(1-\hat m)$, in the `cap` layout; and that `c_prior="uniform"` reproduces the current draws for a fixed `random_state`.
- **Commands:** none (method only).
- **Log:** 2026-10-26: card added by the user. 2026-10-26: started on branch `wp-5/eb-prior`; code and unit tests done (§II.5). ## IV.3 (FIX-3) Unseeded randomness

Scheduled on 2026-11-10 (entry FIX-2 + FIX-3 in §III.2); the code below is the code of `devel`, until the fix is merged.

- `RQBS` (`cap-ml` `87b4d9b`, `cap/models/confidence.py`) has two unseeded sources: it wraps its quantifier in QuaPy's `AggregativeBootstrap`, passing the constructor argument `random_state` (`None` by default) instead of the resolved seed, and `AggregativeBootstrap.predict_conf` draws the bootstrap resamples of the target prevalence in joblib workers (`Parallel(n_jobs=-1)`), from their own global NumPy state, so that even a seed would not reach them; and `predict_ct_range` calls `sampling_index` without a `random_state`, so its bags depend on the global NumPy state.
- The quantifiers built by `experiments/methods.py` use an unseeded `MLPClassifier()`: `kdey()` (`KDEyML(MLP())`, in `QuAcc_NxN` and `O-LEAP`, and in `predist`) and `pacc()` (`PACC(MLP())`, in `RQBS` and `PQ`). `main` never seeds the global NumPy state before fitting a method (the only seeding, `util.py:temp_np_seed`, is temporary and limited to building the dataset), so every fit trains a different MLP. For `PQ` this was observed on 2026-11-10 (card WP-14): two runs of `PQ` on `spambase` × `MLP` with the same code and seeds (`cap-ml` `87b4d9b`) agree on only $3$–$8\%$ of the bags, with differences of the estimate up to $3\cdot10^{-4}$ (vanilla accuracy), $1.2\cdot10^{-3}$ (macro-K) and $0.027$ (macro-F1), and the same MAE; the re-run of `PQ` in `main` for WP-14 differs from the FIX-1 run by as much.
- Seeded or deterministic (checked on 2026-11-10): the bootstrap wrappers `BootstrapCTCAP` and `BootstrapDirectCAP` of `QuAcc_NxN`, `O-LEAP` and `DoC` (`np.random.RandomState(qp.environ["_R_SEED"])` at each call), the split of $V$ and the candidate bags of `PrediQuant`, the internal $5$-fold cross-validation of PACC and KDEy (stratified, not shuffled) and the KDEy aggregation. `L-CBPE` draws no random numbers. `BayCAP`, `BayCAPKDEy` and `BayCAPMAPLS` are not affected: NUTS, their MLP (`methods/baycap_quantifier.py`) and their multinomial draws are seeded.
- **Where:** `cap-ml` for `RQBS`'s bootstrap and bags; UNCAWE (`experiments/methods.py`, `MLPClassifier(random_state=qp.environ["_R_SEED"])`) for the MLPs of the quantifiers.
- **Comparability:** seeding changes the draws and the fitted MLPs. The results of `RQBS`, `PQ`, `QuAcc_NxN` and `O-LEAP` become reproducible but differ from the stored ones within the run-to-run variation (for `PQ`, measured above); their stored results cannot be reproduced bag by bag, and a fix needs them re-run in `main`.

## IV.5 (FIX-5) Interval scores are implemented three times

Coverage, amplitude and Winkler score are computed separately in `tables/main.py` (`get_acc_*`), `plots/common.py` (`interval_metrics`, `winkler_score`) and `experiments/predist.py` (`_interval_metrics`). Fix: one shared module used by all three; the existing tables and plots must not change.

## IV.6 (FIX-6) To verify: smoothed metric used as ground truth

`build_result_frame` (`experiments/records.py`) computes `true_accs` with the `acc_fn` returned by `gen_acc_measure`, which is the *selection* metric: for macro-F1 it is `smooth(f1_macro)` (or `smooth(f1)`), which adds $\varepsilon=10^{-5}$ to every cell. `get_evaluation_acc` (unsmoothed) exists but is not used for the ground truth, and the tables and plots also recompute the truth with `acc_from_ct(..., type="selection")`. Vanilla accuracy and macro-K are unaffected. To check: whether the difference matters for macro-F1 on bags with absent classes, and which version should be the reference.

## IV.7 (FIX-7) README

`README.md` is in Italian and documents only `main`, its tables and the coverage–amplitude plot. It does not cover `binform`, `predist`, `BayCAPFixed`, the extra plots or the tests.

## IV.8 (FIX-8) The smallest class of poker_hand is too small for the validation set

Scheduled on 2026-11-10 (entry FIX-8 in §III.2); the code below is the code of `devel`, until the fix is merged.

- **Problem.** `cap-ml`'s `fetch_UCIMulticlassDataset` calls quapy's `fetch_UCIMulticlassDataset` without `min_class_support`, so quapy drops the classes with fewer than $100$ instances of the full collection. The training part is then capped at `max_train_instances=25000` and halved into $T$ and $V$ (`split_train`, `train_val_split=0.5`), so a class with $s_j$ instances of the $n$ of the collection has about $\lvert V_j\rvert\approx s_j\,n_{\text{train}}/(2n)$ instances in $V$. On `poker_hand` ($n=1{,}024{,}985$, $n_{\text{train}}=25{,}000$) this is $s_j/82$: class 7 ($236$ instances) has $3$ instances in $V$. With so few instances the recalls of $h$ on that class are estimated on almost nothing, and the split of SQS-S with $\rho\in\{0.1,0.9\}$ leaves the class empty in $V_q$ or $V_b$ (E6.2, card WP-17: $10$ failed (pair, level), every classifier of `poker_hand`). The smallest class in $V$ of every other multiclass dataset of `main` has at least $37$ instances.
- **Fix.** A class is kept when its expected count in $V$ is at least $k=10$, $s_j\ge\lceil2k\,n/n_{\text{train}}\rceil$, for every multiclass dataset; the cap is unchanged. Only `poker_hand` changes (threshold $820$; class 7 dropped, $K=7$).
- **Where:** `cap-ml` (a `min_class_support` parameter of `fetch_UCIMulticlassDataset`, pin bump); UNCAWE (the threshold of the rule passed by every caller).
- **Comparability:** `poker_hand` changes ($K$, $T$, $V$, $U$, classifiers): its five classifiers are pretrained again and its results in `main` re-run for every method, and every table, plot and analysis that includes it is regenerated (the list is in the entry FIX-8 of §III.2). The other pairs and experiments are unchanged.

# Part V: Implementation conventions

Each convention is labelled **[general]** (applies to every experiment) or **[specific: \<experiment\>]**, and as *current practice* (what the code does) or *rule* (required for new code). New code follows these conventions; any deviation is stated in the entry of the Part III card that introduces it. A change to a convention states its effect on reproducibility and on comparability with stored results.

## V.1 Experiments

- **[general] Rule. One module per experiment.** `experiments/<name>.py`, with a module docstring that states scope, purpose, target bags, methods and outputs (as in `experiments/main.py`). A shim under `uncawe/<name>.py` is optional; existing shims stay.
- **[general] Current practice. Output location.** `<OUT_DIR>/uncawe/<experiment>/<domain>/<acc_name>/<dataset>/<classifier_full_name>/<method>.parquet`, built with `util.local_path`. `OUT_DIR` comes from `cap.env`, possibly overridden by `env.json` (`env.py`). Logs go to `<OUT_DIR>/<experiment>.log`.
- **[general] Rule. Methods of the experiments.** A method is added to an existing experiment (`gen_methods()` and `METHOD_CLASS` for `main`, the method lists of `binform` and `predist`) only when the user says so, and the card that adds it records that decision; seeds and output paths of existing experiments do not change. Adding a method leaves the stored results of the other methods untouched, so comparability is preserved, but: `all_results_exist` and `get_existing_dataset_names` derive completeness from `get_method_names()`, so every pair counts as incomplete until the new method is stored (`check_missing.py` lists it, and a run of the experiment computes it, skipping the cells that exist); and the tables, ranks and plots of the experiment include it unless they exclude it, so the card states whether the paper artefacts (Part I.4) must stay unchanged and, if so, excludes the method from them. This rule replaces the earlier rule "Frozen experiments" (no new methods in existing experiments; new comparisons in a new experiment directory), changed on 2026-10-21 by the user's decision; the change alone alters no stored result.
- **[general] Current practice. Seeds.** `qp.environ["_R_SEED"] = 0` seeds the target bags and the validation splits. **Rule:** every random choice in new code (bag sampling, surrogate classifiers, MCMC) takes an explicit seed derived from the experiment seed; no reliance on global RNG state.
- **[general] Rule. Shared target bags.** Target bags depend only on the seed, the dataset, the bag index and the protocol, never on the method, so every method in an experiment is evaluated on the same bags.
- **[general] Rule. Label safety.** Target labels are used only for scoring. Variants that use them (true prevalences, oracle priors, oracle-best hyperparameters) are reported as references, never as methods.
- **[general] Current practice. Incremental runs.** A (dataset, classifier, method, metric) cell whose file exists is skipped; deleting a file re-runs that cell.
- **[general] Current practice. Scheduling** (`main`, `binform`). Methods are split into two pools, run one after the other with `run_tasks` (§II.9): regular methods with `cap.env["N_JOBS"]` workers and environment `THREAD_LIMITS`, NumPyro methods (BayCAP and variants) with `BAYES_N_JOBS = 16` workers and environment `BAYES_ENV` (`experiments/methods.py`). `THREAD_LIMITS` sets to 1 the thread-pool variables that `joblib` would otherwise set to `cpu_count() // n_jobs` (4 on `bcuda` with 32 workers): `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `BLIS_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, `NUMBA_NUM_THREADS`, `NUMEXPR_NUM_THREADS`; `predist` applies it to its single pool. `BAYES_ENV` adds `JAX_PLATFORMS=cpu` and single-threaded XLA. JAX defaults to `JAX_PLATFORMS=cpu` (`setdefault` in `experiments/main.py` and `experiments/binform.py`, as the `Makefile`'s `JAX=cpu`), `CUDA_VISIBLE_DEVICES=0`. **Rule.** The cores kept busy by an experiment stay within `cap.env["N_JOBS"]`; idle threads do not count. With 16 BayCAP workers about 24 cores are busy (§II.9, `scripts/bench/bayes_n_jobs.py`). Changed on 2026-10-22 (before: `BAYES_N_JOBS = 1`, no environment for the workers, JAX on `cuda` by default). Reproducibility and comparability: BayCAP draws are identical for every number of workers and, on CPU, for single-threaded and default XLA (§II.9), so BayCAP results on CPU are unchanged; regular methods may differ in the last bits where OpenMP or MKL ran 4 threads per worker, with no statistical effect; serial runs (`N_JOBS=1`) are unchanged.
- **[general] Current practice. Shared constants** (`experiments/methods.py`): `SAMPLE_SIZE = 1000` (bag size), `BOOTSTRAP_ITERS = 1000` (performance samples per bag), `BAYES_WARMUPS = 500`, `CONFIDENCE_LEVEL = 0.95`. **Rule:** new experiments reuse them unless the varied factor is one of them.
- **[general] Rule. Branches.** Each card is developed on its own branch from `devel`, named `wp-<n>/<slug>` for cards and `fix-<n>/<slug>` for fixes (e.g. `wp-1/baycap-estimand`), and merged into `devel` locally, without a pull request: the user reviews the diff from `devel` (`devel...<branch>`), and after approval the branch is optionally rebased on `devel` and merged with `git merge --no-ff`, with a merge commit message that starts with the card or fix ID (e.g. `WP-3: ...`), so that `git log --merges --grep WP-3` finds it. At the merge, the card's `Outcome` field is filled; the merge alone does not move the card, which then moves as described in §III.1. Changes that belong to no card or scheduled fix are committed directly to `devel`. This rule concerns the workflow only: it changes no result, and neither reproducibility nor comparability.
- **[general] Rule. Execution.** Experiments run through the `Makefile`, never from a hand-edited copy of the code: on `bcuda` by default, locally with `WHERE=local`. Each run log `<OUT_DIR>/runs/<name>_<timestamp>.out` starts with the git commit and `git describe --dirty` of the code that ran (remote runs push the working tree first), the host, the command, the GPU and the JAX platform; the environment is the one pinned by `uv.lock` (`uv run --locked`). Raw results stay where they are produced and are merged with `make pull-results` / `make push-results`.
- **[general] Current practice. Environment pins.** `pyproject.toml` constrains `numpyro<0.22`: numpyro 0.22.0 makes `ACC_BayesCAP` fail during NUTS (`TracerArrayConversionError` in the `Multinomial` support check, because the total count is traced), so every BayesCAP task would end in an error. The stored results were produced with numpyro 0.21.0 and jax 0.9.2 (old `bcuda` environment), which the current lock reproduces; the pin therefore restores comparability with them. Remote commands of the `Makefile` set `UV_PYTHON` to `REMOTE_PY` (default `/home/volpi/miniconda3/bin/python3`, Python 3.12.11, the interpreter of the old environment that produced the stored results), because `pyproject.toml` only requires `>=3.12` and uv would otherwise build the remote `.venv` on `bcuda`'s `/usr/bin/python3` (3.14), where `quadprog` (a dependency of quapy) has no wheel and cannot be compiled without the Python headers. This restores the interpreter of the stored results on `bcuda` and changes no result; local environments are not pinned (this machine runs Python 3.14).
- **[general] Rule. `cap-ml` pin** (since FIX-1 + FIX-4, 2026-11-09). `pyproject.toml` takes `cap-ml` at a full commit hash (`rev = "<sha>"`), never at a branch, and `uv.lock` is tracked, so the `cap-ml` commit of a run (and the version of every other dependency, e.g. QuaPy) is the one in the `uv.lock` of the git commit in its run log. A pin bump changes `rev`, runs `uv lock`, and is committed with a note of what changed in `cap-ml` between the two commits and which stored results it affects. Effect on reproducibility: runs are reproducible from their git commit; stored results produced before 2026-11-09 have no recorded `cap-ml` commit.
- **[general] Current practice. JAX platform for NUTS.** BayesCAP runs on CPU (`BAYES_ENV`, since 2026-10-22; before, `JAX_PLATFORMS=cuda` by default). Its model is small and runs a single sequential chain, so it is latency-bound. In a toy timing (`scripts/bench/baycap_platform.py`: `ACC_BayesCAP.sample_posterior`, 500 warm-up iterations, 1000 draws, synthetic counts with seed 0, $K\in\{2,10,26\}$, compilation excluded), one bag took 0.5–1.8 s on the local CPU (ARM, 20 cores) and 3.2–8.9 s on the local GB10 GPU; on `bcuda` it took 1.6–3.8 s on CPU and 6.4–15.4 s on a shared, busy A40. Running with `JAX=cpu` is therefore preferred. Draws are seeded, but CPU and GPU floating point differ, so results computed on different platforms agree statistically, not bit for bit; the run log records the platform. On CPU, single-threaded XLA (`XLA_FLAGS=--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1`) gives results identical bit for bit to the default threading (`scripts/bench/xla_vs_stored.py`, 5 pairs, 2026-10-22). **Rule** (user's decision of 2026-10-22): all BayCAP results of `main` are computed on CPU; the stored `BayesCAP` results, computed earlier on another platform, are recomputed (§I.2). This changes the stored `BayesCAP` results by the amounts reported in §II.9 and therefore the paper's tables slightly; the previous results stay in `<OUT_DIR>/uncawe/main_22_10_26/` (a full copy of `<OUT_DIR>/uncawe/main/` made by the user on 2026-10-22, all methods).
- **[general] Rule. Pilot first.** New experiments are run on a small configuration (few datasets, LR, few bags) before the full grid; NUTS cost is estimated from the pilot.
- **[general] Rule. Runs on request.** After implementing code, only the unit tests are run without asking. Experiments, analyses, table and plot scripts and any other code (pilot or full, locally or on `bcuda`, including `make run-*`) are run only when the user explicitly asks for that run. This rule concerns the workflow only: it changes no result, and neither reproducibility nor comparability.
- **[specific: main] Current practice.** 100 `UPP` bags from $U$. `DoC` (the only method requiring a validation protocol) is fitted on $V_1$ (60% of $V$) and receives 100 `UPP` bags drawn from $V_2$ as its validation protocol (`util.split_validation`, ratio 0.6); all other methods are fitted on all of $V$. This split is unrelated to the SQS-S split.
- **[specific: binform] Current practice.** Bags drawn at Dirichlet prevalences with per-bag seeds `seed + sample_id`; prior constant $c$ as in §II.2.
- **[specific: predist] Current practice.** Own schema and own incremental logic (`predist_io.py`); results are reloaded only if `schema_version` is at least `RESULT_SCHEMA_VERSION`.

## V.2 Methods

- **[general] Current practice. API.** Methods follow the `cap-ml` API. Contingency-table methods subclass `CAPContingencyTable` (with `CTCAPWithConfidence` for intervals) and implement `fit(V, posteriors)`, `predict_ct_range(X, posteriors)` and `predict_ct(X, posteriors)`; they are fitted once, and `switch(acc_fn)` then `ci_from_cts` evaluate each metric on the same table samples. Direct methods (`CAPDirect`) are refitted per metric with `switch_and_fit`.
- **[general] Rule. Location.** New methods live in `uncawe.methods`, one class per module, each with its own test module in `tests/`. Only generic bug fixes go upstream to `cap-ml`, followed by a pin bump (§V, `cap-ml` pin). Helpers shared by several methods are plain functions, not base classes.
- **[general] Rule. Parameters.** Every factor that an experiment varies is an explicit constructor argument, and every class takes a `random_state` that seeds all internal randomness. Bag-sampling methods take the bag size from the target sample unless it is fixed explicitly.
- **[general] Rule. Estimand.** Each method's docstring states whether it targets the population table $C\operatorname{diag}(\pi^Q)$ or the realised table of the target sample, and which uncertainty sources it represents.
- **[general] Rule. Table orientation.** Inside methods, tables follow `cap-ml`: true classes on rows, i.e. $\operatorname{diag}(\pi)C^\top$ for the paper's $C\operatorname{diag}(\pi)$. Docstrings mention the transpose where it matters (as in `QuantifierBayCAP`).
- **[general] Rule. Bayesian quantifiers.** Methods that consume a Bayesian quantifier use joint draws of shape $(m,K)$ on the simplex, never per-class marginal intervals, and validate them. A posterior temperature is called `temperature` in code and $\tau$ in documents.
- **[general] Rule. Naming.** Code names stay as in §I.2. New methods get a code name and, in their docstring, the paper or proposal name. LaTeX labels go in `tables/common.py:METHOD_LATEX_LABELS`, plot labels and colours in `plots/common.py`.

## V.3 Results

- **[general] Current practice. Schema** (`experiments/records.py`, `results.py:ResultsDataFrame`). One row per target bag, with columns `shifts`, `true_cts`, `estim_cts`, `estim_accs`, `estim_acc_ranges`, `acc_err`, `classifier`, `method`, `dataset`, `collection`, `n_classes`, `acc_name`, `train_prev`, `val_prev`, `t_train`, `t_test_ave`. Contingency tables are stored flattened (`_pack_ct`), with true classes on rows; `estim_cts` is the mean of the table samples (`None` for direct methods). Optional columns: `nuts_divergences`, `nuts_max_rhat`, `nuts_min_ess` for the `BayCAP` methods of `main` (§II.5, WP-6) and of `eb_binary` (§II.15), absent from results stored before; for `BayesCAP-H-real` (§II.5, WP-10) also `nuts_failed` and the posterior summaries `h_m_mean`, `h_ln_nu_median`, `h_ln_nu_q05`, `h_ln_nu_q95`, `h_p_nu_above_min_n` (numbers) and `h_recall_mean`, `h_pi_mean`, `h_pi_cov` (vectors of length $K$, $K$ and $K^2$, the covariance row by row); for `BayesCAP-Hf-real` (WP-11) the same columns and `h_ln_kappa_median`, `h_ln_kappa_q05`, `h_ln_kappa_q95`, `h_p_kappa_below_1` (NaN with $K=2$); for the eight methods of E3.1 (`BayCAPKDEy` with `c_prior="fixed"` and `BayCAPMAPLS`, §II.4, WP-8) the three NUTS diagnostics (of $\pi$) and `prev_mean` (vector of length $K$), `acc_sd`, `sigma_g`, `val_ece` (numbers; `val_ece` is the same in every bag of a pair); for the two methods of E3.2 (`BayCAPKDEy` with `c_prior="hierarchical-f"`, §II.4, WP-13) the three NUTS diagnostics (of $\pi$, $C$ and the Hf hyperparameters), the columns of `BayesCAP-Hf-real`, `c_mean` and `c_sd` (vectors of length $K^2$, `cap-ml` layout, row by row), `mismatch`, `n_empty_cells`, `n_class_density_cells` and `val_ece` (numbers; the last three are the same in every bag of a pair). A bag where NUTS produced no draws has NaN draws, tables and diagnostics and `nuts_failed=1`. The new columns change no stored result and no comparability.
- **[general] Rule. Store samples, score later.** Results keep the full performance samples (`estim_acc_ranges`), so coverage at any nominal level, Winkler score and other interval scores are computed after the run and never require re-runs.
- **[general] Rule. Schema changes.** New columns are optional so that old files stay readable; experiments with their own schema carry a `schema_version` column, bumped on every change.
- **[general] Current practice. Loading.** `results.py:Results.load(base_dir, domain, acc_name, dataset, filter_classifiers, filter_methods)` globs the Parquet files and concatenates them.
- **[general] Rule. Never commit outputs.** Results, tables, plots and logs stay out of the repository. Environment-specific paths (`env.json`) are committed, so that every machine runs with the same tracked configuration; this changes no result and no comparability.

## V.4 Tables

- **[general] Current practice.** LaTeX tables built with the pandas `Styler`, written as `tabular` fragments plus a standalone document under `<OUT_DIR>/uncawe/tables/<table>/` (`main`, `rank`, `binform`). CLI flags: `--classic|--text|--image`, `--tables` (fragments and document), `--pdf` (compile only, needs `pdflatex`), `--all`, `--metrics`, `--table-dir`.
- **[general] Rule. Table targets of the `Makefile`.** `EXP_tables-*` targets do not include the mode flag (`--tables`, `--pdf`, `--all`); it is given at call time through `ARGS`, e.g. `make run-tables-main ARGS=--tables` on `bcuda` and `make run-tables-main WHERE=local ARGS=--pdf` to compile the documents where `pdflatex` is installed. Without `ARGS` a table target does nothing. Other flags that select the data (e.g. `--classic`) stay in the target. This rule concerns the workflow only: it changes no result, and neither reproducibility nor comparability.
- **[general] Current practice. Content.** Mean (and optionally std, `--no-std` to hide) per dataset × classifier × method, best value in bold, colour gradient between best and worst, and a $^\dagger$ marker for methods not significantly different from the best under a paired Wilcoxon signed-rank test.
- **[specific: main tables] Current practice.** Metrics `acc_err` and `winkler` (`METRICS`); Wilcoxon over per-bag values at $\alpha=0.01$.
- **[specific: main tables, rank tables] Current practice.** Methods ranked per dataset and classifier by mean value, ranks averaged over datasets; Wilcoxon over per-dataset ranks at $\alpha=0.05$. Since 2026-11-09 (user's decision) the main tables, the rank tables and the coverage vs amplitude plot show the same methods, `tables/main.py:MAIN_METHODS` (eight until FIX-2, nine since): `DoC`, `QuAcc_NxN`, `O-LEAP`, `SQS-H`, `SQS-Hbs` (SQS-H with a bootstrap of the prevalence, `RQBS` before FIX-2, which added `SQS-H` on 2026-11-10), `PQ` (SQS-S), and the Bayesian methods with the realised-table predictive only, `BayesCAP-real` (BayCAP), `BayesCAP-Hf-real` (BayCAP-Hf) and `BayCAP-KDEy-mlp-real` (BayCAP-KDEy with an MLP as input classifier and a fixed $\hat C$); every other method stored in `main` is excluded (`EXCLUDED_METHODS`), among them `L-CBPE` and `BayesCAP` with the population pushforward, which the paper reports. The rank tables keep `L-CBPE` in `tables/rank.py:RANK_ONLY_EXCLUDED` (binary datasets only), and their `--include` options still add excluded methods in a separate folder. Before, the main tables showed the methods of the paper plus `BayesCAP-EB-real`, `BayesCAP-Hf-real`, `BayCAP-KDEy-h-real` and `BayCAP-KDEy-mlp-real` (2026-11-05 and 2026-11-06), and the rank tables the same without `L-CBPE`; on the branch of WP-13 (2026-11-06 to its merge on 2026-11-09) the tables, ranks and coverage vs amplitude plot also showed the two methods of E3.2, which the merge leaves out. This changes the columns, the bold and $^\dagger$ marks and the ranks of the tables of `main`, not any stored result; the paper's Table 1, Table 2 and coverage vs amplitude figure (§I.4) are no longer reproduced by the default method sets. `PQ` is shown with its stored results, re-run after FIX-1 on 2026-11-09 (§I.2); the tables and rank tables of `main` and the coverage vs amplitude plot were generated again on them the same day.
- **[general] Rule.** Reference variants that use target labels appear as separate, unranked columns, excluded from bold and $^\dagger$ marking. Interval scores are computed from the stored samples with the shared implementation (once FIX-5 is done).

## V.5 Plots

- **[general] Current practice.** Matplotlib/seaborn, with `MPLCONFIGDIR` set to a temporary directory. Method colours, plot labels, classifier markers, font scale and facet layout come from `plots/common.py`. Output goes to `<OUT_DIR>/uncawe/plots/<experiment>/<plot_name>/` (`plots/predist.py`: `<OUT_DIR>/uncawe/plots/predist/<dataset>/`) as png plus svg (`--no-svg` disables it); `plots/amplitude_vs_coverage.py` also writes pdf (`--no-pdf`). `--add-stem` appends a suffix to the file name where supported.

The coverage vs amplitude plot (`plots/amplitude_vs_coverage.py:PLOT_METHODS`) shows instead the eight methods of the main tables, `tables/main.py:MAIN_METHODS`, one facet each (user's decision of 2026-11-09; §V.4); before, it showed `DEFAULT_METHODS` plus `BayesCAP-real`, `BayesCAP-EB-real`, `BayesCAP-Hf-real`, `BayCAP-KDEy-h-real` and `BayCAP-KDEy-mlp-real`.

Plot modules.** One module in `plots/` for each group of plots related to the same experiment or analysis (e.g. `plots/displacement.py` for E2.2), with a `--figures` option to select the figures; plots of different experiments go in different modules. Plot modules read stored results only (never re-running methods); new methods are added to the shared colour and label maps rather than defined locally. This rule replaces the earlier "one module per figure" (changed on 2026-10-21 by the user's decision); the existing one-figure modules stay as they are. It concerns code organisation only: it changes no result, and neither reproducibility nor comparability.
